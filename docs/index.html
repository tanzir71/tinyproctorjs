The whole system, on one sheet

No vendor cloud in the loop. The script watches the exam page, scores what it sees, and ships the evidence to an endpoint you own.

  1. Embed

    One script tag

    Auto-initializes from data-attributes. No build step, no framework, no install.

  2. Monitor

    Passive listeners

    Visibility, focus, fullscreen, clipboard, input, screens, activity. Never camera, mic, or contents.

  3. Score

    Weighted locally

    Configurable weights produce a live 0–100 score for instant triage.

  4. Report

    Batched to you

    sendBeacon / keepalive fetch with retry + backoff. Survives page close and page changes. Offline-tolerant.

Fifteen signals, one integrity score

Every signal is individually configurable and weighted. The score gives reviewers instant triage; the event timeline gives them evidence.

SignalViolation key and default weight

Tab switching

Detects when the exam tab is hidden or the browser is minimized, and reports how long the candidate was away.

tab_hidden−10

Focus loss

Flags clicks into other apps and windows — the classic second-screen tell. Moving between answer fields doesn't count.

window_blur−5

Fullscreen exits

Enforce fullscreen at start, get an event the moment a candidate leaves it.

fullscreen_exit−25

Copy / cut / paste

Detects clipboard use anywhere on the page — and can block it outright.

copy_attempt−10cut_attempt−10paste_attempt−15

Drag-and-drop text New

Text dragged into an answer box skips paste events, so drops are counted too. File uploads are ignored.

drop_attempt−15

Bulk text insert New

A whole answer appearing in one go: the trace AI agent browsers and auto-typers leave. Records the length, never the text.

insert_burst−15

Right-click

Context-menu detection with an optional hard block.

context_menu−5

Print attempts

Catches Ctrl/Cmd+P and the browser's print dialog.

print_attempt−10

DevTools heuristics

Key-combo and window-resize heuristics flag console snooping and docked side panels, now also at exam start. Best-effort by design.

devtools_key−20devtools_resize−15

Idle + heartbeat

Inactivity detection plus a 30s heartbeat so dropped sessions stand out server-side.

page_idle−5heartbeat30s

Second screen New

Flags an extended display at start or when one is plugged in. Chrome and Edge, no permission prompt.

multi_screen−10

Browser automation New

Flags WebDriver-controlled browsers via navigator.webdriver. A weak signal: it can be spoofed, so its absence proves nothing.

automation_flag−25

How the score works

score = 100 − ∑(weight × count)clamped to 0–100, recalculated on every event

Example: two tab_hidden events and one paste_attempt give 100 − (2×10 + 1×15) = 65.

  • Turn any signal off individually.
  • Block clipboard and right-click, not just detect them, with data-block-clipboard and data-block-contextmenu.
  • Re-weight anything: data-weights='{"tab_hidden":20}'
  • Count a tab switch once with data-blur-dedupe-ms="500".
Configuration reference

What lands on your server

Events arrive as JSON batches with a session envelope. Your collector stores them however you like — it's one endpoint, in any stack.

  • Survives page close and page changes

    navigator.sendBeacon() on exit, fetch(keepalive) otherwise. Unsent events are saved per tab and sent from the next quiz page.

  • Retries on its own, dedupes exactly

    Failed batches are re-queued with exponential backoff. Every event carries a seq: dedupe on (sessionId, seq), and a gap means something never arrived.

  • Fits the stack you already run

    Copy-paste PHP + SQLite and Node.js collectors in the docs. Drops into Moodle, WordPress (LearnDash, Tutor LMS, Quiz Maker) and custom platforms.

What it deliberately doesn't do

Honest scope beats inflated promises. Client-side signals are indicators for human review — not proof, and not prevention.

No surveillance

No camera, no microphone, no screen recording, no keystroke logging, no clipboard contents. Events describe that something happened, never what was typed or copied.

No false security

A technically skilled candidate can disable any in-page script. tinyproctor.js deters casual misuse and produces an audit trail — for high-stakes certification, layer it with stronger controls.

Questions teams ask first

Short answers here. The docs go deeper.

Does it work on mobile?

Yes — visibility, focus, clipboard, idle, and heartbeat signals all work on mobile browsers. Fullscreen and DevTools signals are desktop-oriented.

Will it slow the exam page down?

No. It's under 7 KB gzipped, dependency-free, uses passive event listeners and batched network calls (one small POST every ~0.9s at most).

What happens if the network drops?

Events queue locally (up to queueMax) and retry with exponential backoff. On page close, the queue is flushed via sendBeacon, which browsers deliver even during unload. With an attempt ID, unsent events are also saved per tab and sent from the next page.

Does it work with multi-page quizzes?

Yes. Put the same tag with the same data-attempt-id on every page: v1.1 keeps one session and one score per attempt, and moving to the next page is not a tab switch. Call TinyProctor.destroy(true) after submit.

Does it catch AI agents?

Partly. Agent browsers tend to type a whole answer at once (insert_burst), WebDriver automation announces itself (automation_flag), and docked AI sidebars trip the side-panel heuristic. A careful agent can avoid all three, and an AI on another device is invisible to any browser script, so treat these as reasons to review, not verdicts.

Can candidates fake a perfect score?

A sufficiently technical candidate can — this is true of every client-side tool. Use heartbeat gaps and missing-session detection server-side to flag tampering: a session with no events at all is itself a red flag.
